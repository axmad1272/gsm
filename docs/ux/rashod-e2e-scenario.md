кликов и перепечаток.

## Решения владельца и что они меняют

| Решение | Состояние | Что сделать |
|---|---|---|
| Закрытие: две проверки текущей редакции + актуальная печать | ⚠️ | Явно проверять, что последний выпуск относится к текущей редакции и не заменён |
| Право закрытия отдельное, по умолчанию у бухгалтера | ⚠️ | Убрать `shipment.close` из набора финансиста |
| Оператор закрытую ТТН не исправляет | ✅ | — |
| Админ-правка сохраняет историю и требует проверки новой редакции | ✅ | Добавить тест на закрытую ТТН |
| Закрытый месяц не обходится админ-правкой | ✅ в коде | Добавить тест |
| Только транспорт → прежняя проверка Didox с её датой и источником | ⚠️ | Поля `didox_checked_at`, `didox_check_source`; сузить условие повторного использования |
| Перемещение видят оба склада, изменение и ПД — отдельно | ⚠️ | Аннулирование, проверки и замечания — с проверкой склада отправления |
| Заглушка Didox — только в явном dev-режиме, без «Проверено» | ❌ | По умолчанию Didox выключен; заглушка ставит отдельный статус «не проверено (заглушка)» |
| Нужна настоящая авторизация | ❌ | Вход по логину и паролю с серверными сессиями (или SSO — выбрать) |

## Что не входит в этот этап

Сверка 1С, перенос данных из текущей системы, реальный адаптер Didox, остальные экраны
(черновики, проверка, история, поиск — только как вкладки реестра).
